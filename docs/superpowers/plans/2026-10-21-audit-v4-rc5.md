# audit-v4-rc5 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring the reviewed rc5 candidate to the tag `audit-v4-rc5`, install it on the testnet instance through the governed upgrade, pass the 19-drill rehearsal against it, and record the result in the docs, before 24 October 2026.

**Architecture:** No contract code changes: rc5 is frozen at the merged candidate (`cea79b6`, hash `6b7c6c80…`). The work is a release sequence: finish and land the docs branch on `main`, tag, run the existing `demo/upgrade.mjs` against the live instance `CBDS6BZ2…` with the expected hash, rehearse with `demo/monitor.mjs --rehearse`, then update the facts the docs and the web carry. Every on-chain step is a script of the repository run from the main checkout, which holds the testnet keys (`demo/.state/testnet.json`, git-ignored) and the installed `node_modules`.

**Tech Stack:** Rust 1.98.1 / `wasm32v1-none` / Stellar CLI 28.1.0 (contract build); Node 22 scripts in `demo/` (upgrade, monitor, inventory); GitHub Actions `ci.yml` (push to `main`) and `pages.yml` (web); git annotated tags.

**Spec:** `docs/roadmap.md` (row "Security pass of 20 October 2026", checklist in `README.md` line 135), `docs/operations.md` section 5 ("Upgrading the code", "The upgrade to rc5", "On upgrade day"), `docs/audit-scope.md` ("What runs, and what is reviewed"), `docs/incident-procedure.md` section 6 (rehearsal).

## Global Constraints

- Contract code is frozen: the tag must build to sha256 `6b7c6c80378297aab8e4e9535555190c07980410ecdde5625673ff7a6b80d478`, 104,624 bytes, stack 65,536 bytes (`docs/audit-scope.md`). Any change to the WASM means a new review, not this plan.
- `version()` answers 4 and `SCHEMA_VERSION` stays 2: the upgrade needs no `migrate`.
- The testnet instance is `CBDS6BZ2JOU6AGIR6FSFK6MNIS25DVYYD2ZHHHEWIPXH4ZDCVWWX7XGL`, delay 5 minutes, running rc4 (`f5f13ae6…`). Three funds, two euro stablecoins.
- On-chain steps run from the main checkout after `main` carries the merge: it alone holds `demo/.state/testnet.json` and `node_modules`. Never run `npm run upgrade` from a worktree without the state file.
- `npm run upgrade` refuses to run while `NIGHT_WINDOW_STACK_SIZE` or `CARGO_TARGET_DIR` is set; build in a clean shell.
- Keeper float before the upgrade: at least 800 XLM plus about 706 XLM for the run's rent (`docs/operations.md` section 4, "Rent").
- Stop every `monitor --watch` before `npm run upgrade`; restart it after (operations.md, "On upgrade day").
- Tags are annotated, on a `main` commit, after CI is green there (`audit-v4-rc4` precedent on `a85515f`). Commits end with the attribution lines of the session's system reminder.
- Docs are in English; one commit per page is the convention of the docs series.
- Deadline: all tasks done by 24 October 2026.

## Review Focus

Operational conditions the scripts handle but no offline test exercises; each is pinned by a check in the task that owns it:

1. A fund whose price reference already left its corridor before the upgrade (the T-bill fund drifts out around 28 October): rc5 then refuses its NAV at once and needs a two-key re-anchor. Pinned in Task 4 (step the references, then read the inventory's corridor column).
2. A pending proposal made under rc4 that rc5 refuses at its apply (names the trustee or the sentinel, backup feed equal to the primary, re-anchor on a non-compliant feed): pinned in Task 4 (hand check of `proposals`).
3. The second RPC endpoint down during the upgrade: the script then takes one endpoint's word on every verdict. Pinned in Task 5 (endpoint check before the run; `STELLAR_RPC_URLS` fallback recorded in the log).
4. A keeper short of the run's rent: the upload leaves the code at a 7-day TTL and the run stops after it. Pinned in Task 4 (balance check) and Task 5 (`--restore-code` recovery path).
5. A `monitor --watch` still running when the proposal lands: it cancels the unannounced proposal as an attack. Pinned in Task 5 (process check before the run).
